# Unity CLI: правила команды

Этот инструмент ускоряет выполнение назначенной задачи, но не расширяет её scope. На архитектурном этапе достаточно чтения состояния; игровую реализацию без отдельного поручения не начинать.

## Подключение

- CLI: `C:/Users/Artem/AppData/Local/Unity/bin/unity.exe`; проверенная версия `1.0.0-beta.15`.
- Unity-проект: `C:/Users/Artem/Desktop/Projects/game-moving-coop/game-moving-coop`.
- Клон GitHub Desktop: `C:/Users/Artem/Desktop/Projects/game-moving-coop`.
- Pipeline: `0.9.1-exp.1`. Editor должен быть открыт. Не фиксировать порт или PID между запусками: выбирать проект через `--project-path`.
- В новом процессе сначала проверить `unity --version`. Если команда не найдена, использовать полный путь, не устанавливать CLI повторно.

Перед работой с редактором:

```powershell
$taskUnity = 'C:/Users/Artem/AppData/Local/Unity/bin/unity.exe'
$taskProject = 'C:/Users/Artem/Desktop/Projects/game-moving-coop/game-moving-coop'
& $taskUnity pipeline editors --json
& $taskUnity command editor status --project-path $taskProject --json
```

Убедиться, что ответ относится к нужному projectPath, Editor доступен и не выполняет компиляцию/domain reload. Поля envelope и результата проверять вместе с exit code: процесс без ошибки не доказывает успешность вложенной операции. Недоступный Editor — ограничение проверки, а не основание считать её пройденной.

## Как ускорять работу

1. Сначала найти нужную операцию: `unity command --project-path <path> --query <term> --json`. Прочитать возвращённые параметры и описание. Использовать `--help` установленного CLI: пример `pipeline list` из документации в beta.15 заменён на `pipeline editors`.
2. Использовать CLI для чтения сцены, иерархии, компонентов, состояния компиляции и console вместо лишнего обхода GUI. Проверенная команда списка сцен: `unity command scene list_open --project-path <path> --json`.
3. При разрешённой реализации предпочитать поддерживаемые редакторские команды для объектов, компонентов, сцен и префабов вместо ручной правки их YAML. C# писать обычными файлами с соблюдением архитектуры; CLI использовать для проверки редакторского результата. Не выполнять произвольный eval, если задачу решает зарегистрированная команда.
4. При необходимости компиляции, Play Mode, тестов или сборки сначала уточнить доступную команду и параметры. Запускать только проверки, требуемые задачей и соответствующие её риску. Для документационных правок запуск Unity-тестов не нужен.
5. После изменения прочитать фактическое состояние, проверить console/компиляцию по задаче и `git diff`. Сохранение сцены — отдельная запись; проверить, какие файлы и .meta реально изменились. Наличие объекта в памяти не доказывает сохранение ассета.
6. У асинхронной команды дождаться конечного статуса предусмотренным механизмом; queued/in_progress не считать успехом. Не повторять изменяющую команду после timeout, пока не выяснено, выполнилась ли она.

## Работа трёх ролей

- **PM:** в задаче указать ожидаемое наблюдаемое состояние, допустимые изменения Editor, необходимые проверки и доказательства; не диктовать устаревшие команды. Если нужен Play Mode/сборка, включить это в критерии соответствующей реализации.
- **Разработчик:** пользоваться CLI для доступных редакторских операций и проверки, не подменять результат кодом завершения процесса. Передавать QA команды, target project, результаты, перечень изменённых файлов и известные ограничения.
- **QA:** независимо сверять Editor и файлы в объёме задачи, использовать read-only CLI-команды. Play Mode, тесты и сборки выполнять только если это предусмотрено проверяемой задачей, когда разработчик освободил Editor. Не исправлять код или сцену в ходе ревью.

Editor общий для всех субагентов. Координатор назначает одного владельца изменяющих команд. Во время QA разработчик не меняет файлы, сцену или Play Mode. Не запускать одновременно компиляцию, тесты, сборку, смену сцены и Play Mode из разных агентов. Чтение, которому нужна стабильная сцена, также согласовывать с владельцем.

Не закрывать/перезапускать Unity автоматически при несохранённых сценах, не сохранять чужие изменения через save_all и не менять пакеты, настройки безопасности, аккаунт или плагины ради устранения ошибки без соответствующей задачи. Для проверенного локального чтения вход в Unity CLI не понадобился; не инициировать облачную авторизацию без необходимости.

## Отчёт

Записывать кратко: команда и projectPath, что проверялось, конечный статус и фактическое наблюдение, изменения файлов, ограничения. Не вставлять полный каталог команд, base64 изображений, токены или персональные сведения. Если проверка не выполнена, так и указать.
