## Обязательное замечание

**[P2] Focus loss / stale input не освобождают участие явно.** Файл `docs/architecture/iteration-01-tech-gate.md`, строка 31; связанный IT1-ADR-003 в decisions.md.

SPEC-001, строка 57, требует при focus loss отправить release/focus, а при authority timeout независимо обнулить ввод **и освободить участие по правилу отпускания**. Gate определяет только нулевое движение/вращение. Сценарий: клиент держит диван и теряет фокус, run-in-background продолжает посылать свежие нулевые сообщения. Без release ручка остаётся занятой; timeout не наступает. При реальном прекращении ввода timeout тоже не предписывает освобождение. Это позволяет реализовать gate буквально с нарушением согласованного ТЗ.

Требуемое уточнение: focus отправляет явное отпускание/focus-событие, authority освобождает удержание/approach reservations; stale 500 мс независимо выполняет тот же безопасный release, включая обе ручки дивана. Обновить краткое ADR-003 согласованно. Не менять согласованные скорости/таймер/числа. После исправления достаточно статической перепроверки этого пункта и новых хешей.

## Что подтверждено

- SHA256 обоих файлов совпали с handoff.
- Независимый `Invoke-RestMethod` к официальным registry подтвердил NGO 2.13.3 minimum Unity 6000.0 и зависимость Transport 2.6.0; Transport 2.6.0 minimum 2022.3, Burst 1.8.24, Collections 2.2.1, Mathematics 1.3.2; NGO 3.1.0 требует 6000.7. Вывод о допустимости Unity 6000.6.7f1 по metadata корректен; UPM resolve/компиляция остаются будущей проверкой.
- Единый host authority, очередь дискретных операций, sender metadata, sequence/ShiftId, две роли и запрет позднего входа соответствуют scope. 20 Hz и 500 мс заданы как проверяемые инженерные параметры.
- Кинематический sweep/overlap учитывает всю сборку, дугу вращения, безопасные подпозы; подход к ручке не равен teleport, reservation отделена от attachment. Тесные повороты и реальные коллизии обоснованно оставлены runtime-приёмке.
- История ARCH-001 отделена от новых решений. Двухпроцессный сценарий идёт через обычный command pipeline и не заменяет UI-проверки.

Источники registry: [NGO](https://packages.unity.com/com.unity.netcode.gameobjects), [Transport](https://packages.unity.com/com.unity.transport). Получены version/unity/dependencies через read-only PowerShell, exit 0.

Единственное изменение QA — этот отчёт. Editor/Unity CLI, код и пакеты не затрагивались; установка, компиляция, Play Mode и игровые тесты не выполнялись и не объявляются пройденными.
