## IT1-06 — окончательная Windows-поставка

На одной версии сборки запустить два отдельных Windows процесса. Зафиксировать PID, команды host/join, конечные логи и запись обоих окон. Использовать обычный игровой путь без принудительной подстановки суммы/таймера:

- **F01:** с исходного состояния сдать восемь коробок → 320; смена продолжается, затем обоим эвакуироваться → успех. Подтвердить выполнение за 300 с и сохранить фактическое время.
- **F02:** новая попытка; сдать диван и три коробки → 320 → эвакуация → успех. Показать реальный совместный проход поворота и двери; уложиться в 300 с.
- **F03:** новая попытка, недобор → дождаться 300 с → провал; после restart с квотой дождаться timeout → успех. Местонахождение участников не меняет правило.
- **F04:** недобор и ранняя ручная эвакуация → провал; проверить экран причины/суммы, выход в подготовку и два restart (можно учитывать уже записанные попытки той же сборки).
- **F05:** disconnect во время переноски и потеря host подтверждены в этой сборке; release и завершение не остались только Editor-проверкой. Проверить включённые в поставку инструкцию запуска/подключения и полный комплект необходимых файлов.

## Решение QA

Каждый ID получает фактический статус и ссылку на evidence. Документ не требует повторять все проверки после любой мелкой правки: повторять дефект и связанные риски, а при финальной сборке — обязательный сквозной набор. Необязательные исходы/среды помечать явно. Существенный дефект — CHANGES_REQUESTED с P0–P3, файлом/строкой и воспроизведением; невозможный обязательный запуск — BLOCKED/NOT_RUN, не PASS. Полная итерация проходит при подтверждённых обязательных сценариях и двухпроцессной Windows-поставке; статическое ревью, прошедшая компиляция и один локальный персонаж сами по себе этого не доказывают.
