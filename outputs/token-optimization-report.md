# Оптимизация работы агентов — 01.11.2026

Внедрено без запуска субагентов и без возобновления игры. ТЗ из Downloads использовано как перечень предложений; шаблонные роли сопоставлены существующим PM/developer/QA, дополнительных ролей нет.

По видимой истории чата: подтверждены частые вызовы PM/QA только ради готовности и статусов, многократные чтения AGENTS/spec, длинные handoff и короткие циклы ожидания. Не все задачи использовали всю тройку — утверждать это для каждой задачи нельзя. Отсутствие журнала подтверждено до внедрения. Применение «дорогих моделей ко всему» и точные расходы не подтверждены: настройки наследовались, телеметрии нет. Источник наблюдений — доступная переписка этого чата, не независимый экспорт биллинга.

Изменения:
- AGENTS и три роли сокращены: 12448 → 4775 символов суммарно, минус61.6%. Это символы инструкций, НЕ измеренное сокращение токенов задачи.
- S выполняет координатор; M обычно один разработчик; L получает PM только при этапах/контрактах; C требует независимого QA. Запуск всей тройки требует обоснования.
- Новые агенты получают fork_turns=none и релевантный пакет вместо полной истории. Подтверждения ready/status не являются самостоятельной работой.
- Лимиты вызовов/раундов и формат200слов вынесены в docs/operations/agent-policy.json. Это исполняемые агентом правила, не жёсткая квота сервиса.
- Модели оставлены наследуемыми: переключение и кэш не имитируются. Экономия прежде всего за счёт количества вызовов и контекста; модельный пилот возможен отдельно.
- Добавлены workflow и журнал usage.jsonl. Точные tokens/cache/cost недоступны и записаны null; историческую базу15–30 задач нельзя восстановить достоверно из этой переписки.

Проверки: три TOML разобраны настоящим Python tomllib, JSON прочитан, assertions маршрутизации/лимитов/паузы прошли. Проверки структуры не доказывают поведение будущих агентов. Тест-кейсы T1–T9 приложенного ТЗ превращены в правила: S/UI без архитектора, L по контрактам, C с независимым QA, отсутствие повторов, ограничение раундов, инвалидация сводок, одна модель как fallback, сохранение ошибок/обязательных тестов. Их реальные игровые прогоны НЕ выполнялись: игра на паузе. A/B, медиана/p90, цели30% и50%, динамика дефектов пока не измерены. План — собирать следующие15–30 естественных задач по классам, не тратить лимит на искусственные запросы.

Игровые файлы, Unity, сборки и тесты игры не изменялись/не запускались. Точка продолжения сохранена. Конфигурация ролей действует для новых запусков; существующие длинные контексты задним числом не очищены.

## Коррекция процесса v2 — 01.11.2026

Предыдущая маршрутизация оставляла разработчика обязательным для M и PM+разработчика для L; это сохраняло лишнюю цепочку даже после сокращения промптов. Теперь небольшие изменения пишет координатор, C получает независимого QA, PM не участвует в локальных правках. Перед делегированием обязателен .codex/check_route.py; это локальная проверка плана, не перехват инструментов и не квота провайдера. Проверено: M без агента разрешён; S с разработчиком отклонён; C с QA разрешён. Модели и игровой код не изменялись. Эту настройку выполнил координатор без субагентов. Фактическое снижение токенов ещё не измерено; успех оценивается на следующих задачах, не по числу написанных правил.
